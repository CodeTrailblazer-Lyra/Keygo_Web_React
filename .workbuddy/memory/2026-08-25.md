## 生产环境一直加载修复 2：rolldown advancedChunks 跨 chunk 循环依赖（凌晨追加）

1. **现象**：上面 3-group 拆包（react-core / antd / vendor）生产部署后页面**卡在加载动画**，Console 抛 `Uncaught TypeError: e is not a function at react-core-b9jBKUd0.js:1:49`。本地 build 通过、preview 看着也是 200，但浏览器实际无法初始化 React。
2. **根因诊断**：抓 dist 产物看 chunk 头发现 `react-core` chunk 开头是 `import {f as e} from "./request-CFTXwx6Z.js"`——react-core（被 react 用的 CJS 互操作辅助函数依赖）跨 chunk 引用了业务共享 chunk `request`，而 `request` 又 import antd、`antd` 又 import react-core，形成 `react-core → request → antd → react-core` 的循环依赖图。ESM 沿环执行时，`var` 声明暂未初始化就被读到 → `e is not a function`。Rolldown PR #8227 指明这类跨 chunk 循环会导致 TDZ/未定义崩溃。
3. **修复方案**：vite.config.ts 加 `output.strictExecutionOrder: true`（rolldown 1.2.5 支持，强制跨 chunk 按依赖顺序执行、把 CJS 互操作辅助函数抽到独立的 `rolldown-runtime-*.js` 叶子节点）；vendor 分组从 3 层（react-core/antd/vendor）改为 1 层 catch-all（`/[\\/]node_modules[\\/]/`），所有三方 + 辅助函数统一在一个 chunk 内，环自然消失。
4. **防回归**：新增 `scripts/check-chunk-cycles.mjs`（DFS 扫 dist/assets 中 JS chunk 的 import 图，检测循环依赖），挂进 `npm run build`（顺序：tsc -b → vite build → check-chunk-cycles → compress.mjs）。任何未来改动若再生成跨 chunk 环会在 build 阶段直接报错。
5. **产物对比**：
   - 修复前（3 组）：react-core 189KB + antd 868KB + vendor 84KB，但运行时崩溃。
   - 修复后（1 组 + strictExecutionOrder）：vendor 1211KB raw / 386KB gzip / 312KB brotli；`rolldown-runtime-*.js` 独立叶子节点（无 import，~1KB）；keygo_web_react 业务共享 chunk 14KB。整个产物 1267.8KB raw → 405.3KB gzip → 331.1KB brotli。
6. **真实浏览器验证**（而非仅 build 通过）：本地 `vite preview` 起 4181 端口，用系统 Chrome `--headless=new --dump-dom` 渲染 → DOM 中 `<div id="root">` 内已挂载 `<div class="css-s9cfp7 ant-app"><div class="login-page">...`，确认 React 初始化成功、antd 渲染成功。同时截图看到完整 KeyGo 登录页。
7. **学习**：Vite 8 + rolldown 的 `advancedChunks` + `manualChunks: function` 都不可靠；正确的 vendor 拆包必须配套 `strictExecutionOrder: true` 或干脆不分组。`includeDependenciesRecursively` 默认 true 但对代码生成阶段注入的虚拟运行时模块（互操作辅助函数）无效——必须靠 strictExecutionOrder 显式让 rolldown 把它当叶子节点抽出。
8. **MEMORY.md 更新**：技术栈条目改为「全部本地打包」+ 移除 CDN 外部化段；构建与依赖注意追加 Vite 8 / rolldown 分包关键条目，记录 strictExecutionOrder + 环检测脚本。
